# 権限・セキュリティ設計

> 状態: 確定（2026-10-31 に改訂。下の「変更履歴」を参照）

## 目的
誰が何をできるかと、その守り方を定める。

## 決定済み
- MVP: 管理画面は合言葉、司会の操作は秘密トークン付きの司会 URL で守る
- MVP の後: Clerk ログインに置き換える
- 司会の操作はサーバー側で、司会トークンで名乗った接続（host）からの要求かを確かめる（#8）
- 重複参加の対策：①ブラウザに参加コードを保存 ②ニックネームの重複を禁止 ③司会が参加者を削除できる ④景品を渡すときに顔を見て確認 ⑤受付で配る1人1枚の参加コード（1回だけ新規参加に使える）
- 参加コードは復帰コードも兼ねる（使用済みのコードを入れると、新規参加ではなく元のカードに戻る）
- 司会URLは複数人で共有してよい（全員同じ権限）
- **管理画面（ルームの一覧・作成・削除）には管理用の合言葉が必要**。合言葉は Cloudflare の Secret（`wrangler secret`）に保存し、コードやリポジトリには書かない
- 合言葉の確認はサーバー側で行う
- 司会トークンは、ルーム一覧で司会用 URL を再表示するため、元の値で保存する（ルーム一覧は合言葉で守る）
- 参加コードも、司会が再表示できるよう元の値で保存する（司会トークンがある場合だけ返す）
- **参加コードの差し替えを MVP に入れる**（F-11）。司会画面で参加者のコードを新しいものに替えると、古いコードは無効になる。カードと結果はそのまま
- **司会用 URL を作り直せる**。管理画面から新しい司会用 URL を発行すると、古い URL は使えなくなる
- **司会の操作の記録（操作ログ）は残さない**
- **投影画面の URL は保護しない**（スクリーンで全員が見ている情報しか出ないため）

## 本文

### 1. 役割と権限
| 役割 | どうやって確かめるか | できること |
|---|---|---|
| 管理者 | 合言葉 | ルームの一覧・作成・削除、司会用 URL の表示・作り直し |
| 司会 | 司会トークン（司会用 URL） | 開始・抽選・終了、コードの発行・印刷・差し替え・無効化、参加者の削除、コードの再表示、CSV の書き出し |
| 投影 | なし（ルームの URL を知っていればよい） | 公開 state を見るだけ |
| 参加者 | 参加コード | 自分のカードと結果を見る |
| 名乗っていない接続 | — | 公開 state を見るだけ（投影と同じ） |

- 権限の確認はすべてサーバー側で行う。画面でボタンを隠すのは使いやすさのためで、守りにはならない
- 公開 state には、投影画面に出してよい情報しか入れない（#8 の2章）。だから投影画面や名乗っていない接続を守る必要はない

### 2. 秘密の値
| 値 | 作り方 | 保存場所 | 漏れたときの対応 |
|---|---|---|---|
| 合言葉 | 管理者が決める（12文字以上を推奨） | Cloudflare の Secret（`ADMIN_PASSPHRASE`） | `wrangler secret put` で変える（下の 2-3） |
| 司会トークン | 暗号論的な乱数（256ビット。URL で使える文字） | BingoRoom と RoomDirectory に元の値で保存 | 管理画面で作り直す（2-4） |
| 参加コード | 暗号論的な乱数（2-1 の形式） | BingoRoom に元の値で保存 | 司会画面で差し替える（2-5） |
| ルーム ID | 暗号論的な乱数（12文字） | URL に使う | 秘密ではないが、推測されにくくして、関係ない人がルームを見つけられないようにする |

#### 2-1. 参加コードの形式
- **6文字**。表示と印刷は `K7P-3QX` のように3文字ずつハイフンで区切る
- 使う文字は、読み間違えやすい文字（0・O・1・I・L）を除いた英大文字と数字の31種類：`23456789ABCDEFGHJKMNPQRSTUVWXYZ`
- 組み合わせは約8.9億通り。1ルームのコードは最大150枚なので、当てずっぽうで当たる確率は1回あたり約600万分の1
- 入力するときは、大文字・小文字の区別をせず、ハイフンや空白はあってもなくてもよい

#### 2-2. 試行回数の制限
| 対象 | 制限 | 超えたとき |
|---|---|---|
| 参加コード（`join`・`resume`） | 1つの接続で、間違いが1分間に5回まで。1ルーム全体で、10分間に100回まで | 「しばらくしてからもう一度お試しください」と表示し、一定時間受け付けない |
| 合言葉（管理画面） | 同じ接続元から、間違いが10分間に5回まで | 10分間受け付けない |
| 司会トークン（`authHost`） | 1つの接続で、間違いが1分間に5回まで | その接続を切る |

- 接続元を見分けるために IP アドレスを使う場合も、メモリの中で数えるだけにし、保存はしない（#5：IP アドレスは保存しない）
- 合言葉や司会トークンを比べるときは、比べる時間で中身が推測されない方法を使う

#### 2-3. 合言葉を変えるとき
1. `wrangler secret put ADMIN_PASSPHRASE` で新しい合言葉を設定する
2. すでに作ったルームには影響しない（司会トークンは合言葉と関係ないため、司会用 URL はそのまま使える）
3. 管理画面を開いている人は、次の操作で「合言葉が違います」と出るので、新しい合言葉を入れ直す

#### 2-4. 司会用 URL を作り直すとき（司会トークンの作り直し）
- 管理画面のルーム一覧に [URL を作り直す] を置く（確認ポップアップあり）
- 作り直すと、古いトークンはすぐ使えなくなる。古いトークンで開いている司会画面には「司会用 URL が変更されました」と表示し、接続を切る
- 新しい司会用 URL を、管理画面に表示する

#### 2-5. 参加コードの差し替えと無効化（F-11）
- **差し替え**：司会画面の参加者一覧の [⋯] から「コードを差し替える」を選ぶ（確認ポップアップあり）
  - 新しいコードを作ってその参加者に紐づけ、古いコードは無効（revoked）にする
  - カード・リーチ・ビンゴの記録はそのまま
  - 古いコードで開いている端末には「このコードは使えなくなりました」と表示し、接続を切る
  - 新しいコードは司会画面に大きく表示し、司会が本人に伝える（その場で紙に書いて渡す、など）
- **無効化**：参加コードタブで、未使用のコードを無効にできる（紛失した未使用のコードが使われないようにする）

### 3. URL に含まれる秘密の値の扱い
- 司会用 URL の `?t=` と個別 QR の `?c=` は、ページを開いたら画面のプログラムが読み取り、**すぐにアドレスバーから消す**
  - 理由：司会画面を投影したり、画面を人に見せたり、URL をコピーして共有したりしたときに、秘密の値が漏れないようにするため
- 読み取った値の保存先
  - 司会トークン：ブラウザのタブの中だけ（sessionStorage）。タブを閉じたら、司会用 URL を開き直すか、管理画面から開く
  - 参加コード：ブラウザ（localStorage）にルームごとに保存する（#7。開き直したときの復帰に使う）
- WebSocket の URL には秘密の値を入れない（#8）

### 4. 管理画面の合言葉の保持
- 一度入れた合言葉は、ブラウザのタブの中だけ（sessionStorage）に保存する。タブを閉じたら消える
- 管理画面の操作のたびに、合言葉を RoomDirectory の callable の引数として送る（通信は暗号化されている）
- ブラウザに長く残すこと（localStorage や Cookie）はしない

### 5. 入力と出力の安全
- **通信**：HTTPS／WSS だけを使う（Cloudflare Workers の標準）
- **ニックネーム・ルーム名**：前後の空白と制御文字を取り除き、長さを確かめる（#7）。画面には文字として表示し、HTML として解釈させない（React の標準の表示方法を使う）
- **CSV**：Excel で開いたときに式として動かないよう、`=` `+` `-` `@` で始まる値の前に `'` を付ける
- **不適切なニックネーム**：MVP では禁止語の仕組みは作らず、司会が削除する（F-08）。次期に禁止語を検討する

### 6. 荒らし対策のまとめ
| 起こりうること | 対策 |
|---|---|
| 関係ない人がルームを作る | 合言葉（2章） |
| 関係ない人がルームを見つける | ルーム ID を推測されにくくする（2章） |
| 参加コードを当てずっぽうで試す | コードの組み合わせを多くし、試行回数を制限する（2-1・2-2） |
| 1人が何枚もカードを持つ | 参加コード1枚につき1人。景品は顔を見て渡す（決定済み⑤④） |
| 参加者が多すぎる | 上限100人（#7） |
| 不適切なニックネーム | 司会が削除する（F-08） |
| 抽選の連打 | 確認ポップアップと、3秒の間隔（#3・#8） |
| 参加コードが盗まれた | 差し替え（2-5） |
| 司会用 URL が漏れた | 作り直し（2-4） |

### 7. 本人確認（参加コードを伝え直すとき）
- 社内の顔見知りが集まるイベントなので、**司会が口頭で確認すれば十分**とする（名乗った人がニックネームの本人か、周りの人に確かめる、など）
- 不安な場合は、コードを伝え直す代わりに「コードの差し替え」を使い、新しいコードを本人に渡す（古いコードを他人が知っていても使えなくなる）

### 8. Clerk への移行方針（次期）
- 管理画面の合言葉を、Clerk のログイン（自社の担当者だけ）に置き換える
- ルーム一覧の各行に「作成者（Clerk のユーザー）」を記録する
- 司会画面も Clerk のログインで守るか、司会用 URL の共有を残すかは、次期に決める（ログインしていない手伝いの人も司会をできるようにしたい場合は、URL の共有を残す）
- 参加者はこれまでどおりログイン不要
