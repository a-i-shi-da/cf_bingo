# 企画概要

> 状態: 確定（2026-10-31 に改訂。下の「変更履歴」を参照）

## 目的
何を・誰のために・なぜ作るかを定める。

## 概要
自社のイベント（まずは忘年会・新年会）で使う、リアルタイムのビンゴ大会アプリ。
参加者は自分のスマホでカードを開き、司会が番号を引くと、参加者のカードとスクリーンに同時に反映され、自動でマークが付く。
紙のビンゴカードの配布・回収、番号の聞き逃し、手作業でのビンゴ確認をなくす。受付では1人1枚の参加コードを配り、1人1枚のカードで公平に遊べるようにする。

## 利用者
| 役割 | 誰か | 使う端末・画面 |
|---|---|---|
| 主催者・司会 | 自社のイベント担当者 | 手元のスマホまたはPC（司会画面で操作する） |
| 投影 | 会場の投影用PC（当日は操作しない） | スクリーンに映す投影画面（表示のみ） |
| 受付 | 司会または手伝いの人 | 印刷した参加コードを1人1枚配る |
| 参加者 | 社員などイベント参加者（〜100人） | 自分のスマホ |

- **自社のイベント専用**。ルームを作れるのは自社の担当者だけ（MVP は管理画面の合言葉と、秘密トークン付きの司会 URL。後で Clerk ログイン）
- 参加者はログイン不要（受付で配る参加コード＋QR コード＋ニックネーム。参加コードで重複参加を防ぎ、端末を変えたときの復帰にも使う）

## 最初の利用場面
- 忘年会・新年会（2026年12月〜2027年1月ごろ）
- 会場は宴会場など。会場の Wi-Fi やモバイル回線が不安定な可能性がある

## 成功の基準
以下の5つはどれも欠かせない。数値は非機能要件（#5）で確定する。
1. **当日止まらない** — 接続が切れても自動で復帰し、最後まで続けられる。**一度参加した人は、その後つながらなくなっても当選できる**（判定はサーバー側で続け、つながったときに結果が見える）
2. **全員が迷わず参加できる** — 参加コードを受け取り、QR コードを読んでから約30秒以内にカードが表示される
3. **抽選が遅れずに届く** — 番号を引いてから約1秒以内（混んだ会場でも2秒以内）に、全員の画面と投影画面に反映される
4. **盛り上がる** — 演出やリーチ/ビンゴの表示で会場が盛り上がる
5. **公平である** — 1人1枚のカードで参加する（参加コードで重複参加を防ぐ）

## スコープ
### やること
- 会場で集まって行うイベント
- 複数のルームを作れる（イベントごとにルームを作る）
- 投影画面と司会の操作画面を分ける
- 参加コードの発行・印刷と、それを使った参加・復帰
- 途中参加（それまでに引いた番号は自動でマークする）

### やらないこと
- オンライン配信イベント（離れた場所からの参加）
- 課金・決済
- 多言語対応（日本語のみ）
- 社外の人がルームを作れる公開サービス化
