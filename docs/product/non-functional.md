# 非機能要件

> 状態: 確定（2026-11-01 に改訂。下の「変更履歴」を参照）

## 目的
性能・信頼性・コスト・データの扱いの基準を定める。テスト計画（test-plan.md）はこの基準で合否を決める。

## 決定済み
- Cloudflare Workers + Durable Objects（Agents SDK）で動かす
- **データの保存期間：終了から7日後に自動で削除する**（削除までは全員が最終結果を見られる）
- **同時接続数：1ルームあたり110接続まで動作を保証する**（参加者100人＋司会・投影画面・再接続の余裕）
- **対応ブラウザ：iPhone Safari／Android Chrome／LINE アプリ内のブラウザ／PC の Chrome・Edge**
- **料金プラン：無料プランで始め、本番前の負荷試験の結果を見て、有料プランにするか決める**
- **個人情報：ニックネームだけを保存する**。氏名・メールアドレスなどは集めない
- **抽選の反映：普通の回線では約1秒以内（目標）、混んだ会場のWi-Fiでも2秒以内（合格の上限）**
- **参加者1人あたりの通信量は、1ゲームで数百 KB 以内を目標にする**。参加者のスマホに送るのは、引かれた番号・人数・ビンゴした人・自分の結果だけに絞る（参加者一覧の全体は司会画面にだけ送る）

## 本文

### 1. 性能
| 項目 | 目標 | 測り方 |
|---|---|---|
| 同時接続数 | 1ルームあたり **110接続**（参加者100人・司会・投影画面の合計） | 負荷試験で110接続を張り、抽選を75回行って取りこぼしがないこと |
| 番号が届くまでの時間 | 司会が確認の「抽選する」を押してから、全員の画面に反映されるまで **約1秒以内（目標）／2秒以内（混雑時の上限）** | 負荷試験で、110接続すべての受信時刻を記録して確認する（演出の時間は含めない） |
| 参加者の通信量 | 1ゲームあたり **数百 KB 以内**（最初のページの読み込みを除く） | 負荷試験で、1接続あたりの受信量を記録する |
| 参加にかかる時間 | 個別QRを読んでからカードが表示されるまで **約30秒以内**（ニックネームの入力を含む） | 実機リハーサルで、IT に詳しくない人にも試してもらう |
| 画面の表示 | 会場のモバイル回線（4G 程度）で、参加画面が **3秒以内** に表示される | 実機で確認する。参加画面は軽く作る |

- 複数のルームを同時に開いても、ルームどうしで性能に影響しない（1ルーム＝1 Durable Object）
- 参加人数の上限は参加者100人（#7）

### 2. 信頼性（当日止まらない）
- **自動再接続**：接続が切れたら、間隔を少しずつ空けながら自動で再接続を続ける。参加者の操作は不要
- **切断の表示**：切れてから数秒たっても戻らないときは、画面に「再接続中」と出す。カードはそのまま見られる
- **再接続したとき**：サーバーから最新の状態（引かれた番号・自分のリーチ/ビンゴ）を受け取り直し、切れている間の結果も反映する
- **スマホがスリープから戻ったとき**も同じように再接続する
- **状態はすべてサーバーにある**：投影画面・司会画面・参加者画面のどれを再読み込みしても、状態は失われない
- **一度参加した人は、つながっていなくても当選できる**（#1・#3）
- 会場のネットワークそのものが止まった場合はアプリでは対応できない。そのときの代わりの手段は operations.md で決める

### 3. 対応環境
| 端末 | ブラウザ | 主な用途 |
|---|---|---|
| iPhone | Safari | 参加者 |
| Android | Chrome | 参加者 |
| スマホ全般 | LINE アプリ内のブラウザ | 参加者（LINE の QR リーダーで読んだ場合） |
| PC | Chrome／Edge | 司会・投影・参加コードの印刷 |

- 各ブラウザの「最新と、その1つ前のバージョン」を対象にする
- 司会画面はスマホ（上の参加者用ブラウザ）でも操作できるようにする（#2：手元のスマホまたはPC）
- LINE アプリ内のブラウザでは、ブラウザに保存した参加コードが消えることがある。その場合も参加コードを入れ直せば復帰できる（F-21）
- 上の一覧にないブラウザ（PC の Safari・Firefox など）は、動けばよいものとし、テストはしない

### 4. コスト
- 無料プランで始める。100人規模の1回のイベントなら、無料プランの上限には届かない見込み
- 上限の数値は、2026-11-01 に Cloudflare の公式ドキュメントで確かめた（下の表）。1日の上限は UTC の 0時（日本時間の朝9時）にリセットされる。上限を超えると、その種類の操作がエラーになる

| 項目 | 無料プランの上限 | 1回のイベント（100人）の見込み |
|---|---|---|
| Workers のリクエスト | 1日 100,000 件 | ページの読み込みなどで数千件（負荷試験1回で 148 件） |
| Worker の CPU 時間 | 1リクエストあたり 10ms | 負荷試験の日（148 件）：P50 1.01ms・P90 2.04ms・**P99 183ms・P999 517ms**。上限を超えるリクエストがあった（ページの表示の初回と考えられる）。本番のページを50回開いて失敗は0回（2026-11-01） |
| Worker の大きさ | 64 MiB（圧縮前） | 約 7 MiB（Phase 2 の時点。gzip で約 1.4 MiB） |
| Worker の起動時間 | 1秒 | — |
| Durable Objects のリクエスト | 1日 100,000 件（HTTP・RPC・WebSocket の接続・アラーム。**受け取る WebSocket メッセージは 20件で1件**。送るメッセージは数えない） | 接続 110＋再接続の分と、callable（参加・抽選など数百回 ÷ 20）で数百件（負荷試験1回で BingoRoom 483 件・RoomDirectory 17 件） |
| Durable Objects の実行時間 | 1日 13,000 GB-s（ハイバネーションできる間は数えない） | 負荷試験1回（約4分）で BingoRoom 1.44・RoomDirectory 0.31 GB-s。2時間ずっと起きていたとしても 128MB × 7,200秒 ≒ 900 GB-s（上限の約7%） |
| SQLite の読み取り | 1日 500万行 | 負荷試験1回で約 9.7万行（上限の約2%） |
| SQLite の書き込み | 1日 10万行 | 抽選のたびに全員の記録を書くと 75回 × 100人 ≒ 7,500行。**変わった人だけを書く**ようにする（Phase 4）。負荷試験1回で約 3,000行（上限の約3%） |
| 保存できる量 | 合計 5 GB | ごくわずか（BingoRoom 270kB・RoomDirectory 135kB） |

- 出典：[Durable Objects の料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[Workers の上限](https://developers.cloudflare.com/workers/platform/limits/)
- 本番前の負荷試験で、1回のイベントでどれだけ使うかを測る。余裕がなければ有料プラン（月額およそ5ドル〜）に切り替える
- 判断の期限：本番の1週間前まで（operations.md の当日チェックリストに入れる）

### 5. データと個人情報
- 保存する個人に関わる情報は **ニックネームだけ**。氏名・メールアドレス・電話番号などは集めない
- **ニックネームはほかの人に見られる**（ビンゴした人は投影画面とほかの参加者の画面、全員分は司会画面と CSV）。参加画面に「スクリーンや参加者の画面に表示されます。本名でなくてもかまいません」と案内する。見える場所の一覧は screens.md の 2-1
- アプリで IP アドレスや端末の情報を保存しない。Cloudflare 側のログは、調査に必要な期間だけ残す設定にする（期間は operations.md で決める）
- ルームのデータは終了から7日後にすべて削除する（F-15）
- 終了しないまま放置されたルームは、最後に使われてから30日で削除する（#7）
- CSV で書き出した結果（F-10）の管理は、書き出した司会の責任とする

### 6. 見やすさ・使いやすさ
- 参加画面は片手で操作でき、文字はスマホで読みやすい大きさにする
- 投影画面の番号は、会場の後ろの席からも読める大きさにする
- マーク済み・リーチ・ビンゴは、色だけでなく形や文字でも区別できるようにする（色の見え方が違う人への配慮）
- 日本語の Web フォントは読み込まず、スマホに入っているフォントを使う（通信量を増やさないため。#6 で決定）

### 7. 監視
- Cloudflare のログ機能（Workers のログ）を有効にして、当日のエラーをあとから調べられるようにする
- 司会画面で、参加者の接続状態を見られる（F-07）。当日の様子はここで確認する
