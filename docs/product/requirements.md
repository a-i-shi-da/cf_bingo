# 機能要件

> 状態: 確定（2026-10-31 に改訂。下の「変更履歴」を参照）

## 目的
機能の一覧・優先度・受け入れ条件を定める。実装とテストは、ここにある機能 ID（F-xx）で対応を取る。

## 決定済み
- MVP（最初の忘年会に間に合わせる版）には、#1〜#3 で決まった機能に加えて **抽選の演出・効果音** と **結果の書き出し** を入れる
- **ビンゴ申告と司会の承認はやらない**（サーバーの自動判定で当選が決まる。申告制にすると、つながっていない人が当選できなくなる）
- **参加コードは、コードごとに個別の QR を印刷する**（読むだけでコードが入力される）。QR が読めないときのために、コードの手入力もできるようにする
- **ルームのリセット機能は作らない**。リハーサルはリハーサル用のルームで行う
- 次期：景品管理、ニックネームの禁止語、Clerk ログイン
- **終了したゲームは、終了から7日後に自動で削除する**。削除されるまでは、全員が最終結果を見られる
- **1つのルームで遊べるゲームは1回だけ**。2回戦をする場合は新しいルームを作り、参加コードも配り直す
- 複数のルームは同時に開ける。ルームどうしは互いに影響しない
- **司会は複数人で担当できる**。同じ司会URLを共有し、全員が同じ権限を持つ（MVP では役割を分けない）

## 本文

### 機能一覧
優先度：**MVP** ＝ 最初の忘年会に必要／**次期** ＝ MVP のあと／**やらない**

#### 司会（`/`・`/host/[roomId]`）
| ID | 機能 | 優先度 | 受け入れ条件 |
|---|---|---|---|
| F-01 | ルーム作成 | MVP | 管理用の合言葉を入力しないとルームを作れない（合言葉が違うと作成しない）。ルーム名と合言葉を入れて作成すると、司会用URL（トークン付き）が表示される。トークンがない、または間違っていると司会画面を操作できない |
| F-02 | 参加コードの発行 | MVP | 枚数を指定して発行できる。足りなくなったら追加で発行できる。コードはルーム内で重ならない |
| F-03 | 参加コードの印刷 | MVP | 印刷用ページで、1枚ごとに「コード入りQR」「手入力用のコード」「ルーム名」が並ぶ。ブラウザの印刷機能で A4 に複数枚を印刷できる。使用済みかどうかが分かる |
| F-04 | ゲーム開始 | MVP | 「開始」を押すと、投影画面と参加者の画面が「ゲーム中」に変わる |
| F-05 | 抽選 | MVP | 「抽選」→ 確認ポップアップで「はい」を押すと番号が1つ決まり、約1秒以内（混雑時でも2秒以内）に投影画面と全参加者に反映される。「いいえ」なら何も起きない。抽選後の数秒は次を受け付けない。複数の司会端末からほぼ同時に「抽選」を押しても、番号は1つしか出ない。75個引いたら抽選できない。取り消しはできない |
| F-06 | ゲーム終了 | MVP | 「終了」→ 確認ポップアップで「はい」を押すと終了し、全画面に最終結果が出る。終了後は抽選できない。元に戻せない |
| F-07 | 参加者一覧 | MVP | ニックネーム・接続状態（オンライン/オフライン）・リーチ数・ビンゴ（順位・何回目の抽選か）を一覧で見られる。オフラインの人も表示される。複数の司会端末で開いていても、同じ内容がリアルタイムに表示される |
| F-08 | 参加者の削除 | MVP | 一覧から参加者を削除できる（確認ポップアップあり）。削除された人の画面には「削除された」旨を出し、その参加コードでは参加できなくなる。順位は付け直さない |
| F-09 | ニックネーム検索とコード再表示 | MVP | ニックネームの一部で参加者を検索し、その人の参加コードを表示できる。コードは司会画面にだけ出る（投影画面には出ない） |
| F-10 | 結果の書き出し | MVP | ゲーム中・終了後に、参加者一覧とビンゴ順位を CSV でダウンロードできる。Excel で開いても文字化けしない |
| F-14 | 終了後の表示 | MVP | 終了から削除までの間、参加者は自分のカードと最終結果を、投影画面は最終結果を、司会は結果と CSV 書き出し（F-10）を見られる。新しい参加・復帰以外の操作はできない |
| F-15 | 終了したルームの自動削除 | MVP | 終了から7日後に、ルームのデータ（ニックネーム・参加コード・カード・抽選結果）がすべて自動で削除される。削除後に URL を開くと「このルームは終了し、削除されました」と表示される |
| F-16 | ルーム一覧 | MVP | `/` で合言葉を入れると、作ったルームの一覧（ルーム名・状態・作成日・削除予定日）が見られ、各ルームの司会用 URL を表示・コピーできる。司会用 URL をなくしても、ここから司会画面に戻れる |
| F-19 | ルームの手動削除 | MVP | ルーム一覧から、開始前（waiting）と終了後（finished）のルームを削除できる。削除する前に、ルーム名を入力させて確認する。ゲーム中（playing）のルームは削除できない。削除すると元に戻せない |
| F-17 | 参加人数の上限 | MVP | 1ルームに参加できるのは100人まで。超えると「定員に達しました」と表示する。参加コードは1ルーム150枚まで発行できる |
| F-18 | 放置されたルームの自動削除 | MVP | 「終了」を押さないまま、最後に使われてから30日たったルームは自動で削除される |
| F-11 | 参加コードの差し替えと無効化 | MVP | 参加者一覧から、参加者のコードを新しいものに差し替えられる（確認ポップアップあり）。古いコードは使えなくなり、古いコードで開いている端末は切断される。カードと結果はそのまま。未使用のコードは参加コードタブで無効にできる |
| F-40 | 司会用 URL の作り直し | MVP | 管理画面のルーム一覧から、新しい司会用 URL を発行できる（確認ポップアップあり）。古い URL はすぐ使えなくなり、古い URL で開いている司会画面は切断される |
| F-12 | 景品管理 | 次期 | 景品の一覧を登録し、ビンゴした人に割り当てて投影画面に表示する |
| F-13 | Clerk ログイン | 次期 | 自社の担当者だけがルームを作成・司会操作できる（トークン方式を置き換える） |

#### 参加者（`/room/[roomId]`）
| ID | 機能 | 優先度 | 受け入れ条件 |
|---|---|---|---|
| F-20 | 参加 | MVP | 個別の QR を読むとコードが入った状態で開き、ニックネームを入れて「参加」を押すとカードが表示される（目標：QR を読んでから約30秒以内）。コードを手で入れても参加できる。未発行・無効なコードは拒否する。同じルームで使われているニックネームは使えない。ニックネームがほかの人に見られることを、入力欄の近くに表示している。途中参加もできる |
| F-21 | 復帰 | MVP | 同じブラウザで開き直すと、入力なしで自分のカードに戻る。別の端末で使用済みのコードを入れると、新しく参加するのではなく元のカードに戻る |
| F-22 | カード表示と自動マーク | MVP | 5×5 のカードが表示され、引かれた番号は自動でマークされる。途中参加・再接続のときも、それまでの番号がすべてマークされている |
| F-23 | リーチ・ビンゴの表示 | MVP | リーチ（本数）とビンゴ（順位）が本人の画面に表示される。切れている間にビンゴになった場合も、再接続したときに分かる |
| F-24 | 接続状態の表示と自動再接続 | MVP | 接続が切れると画面に表示が出て、自動で再接続を試みる。つながったら最新の状態に戻る |

#### 投影（`/screen/[roomId]`）
| ID | 機能 | 優先度 | 受け入れ条件 |
|---|---|---|---|
| F-30 | 投影画面 | MVP | 操作ボタンはなく、表示だけを行う。開始前：参加人数（と参加案内）。ゲーム中：今引いた番号（大きく）・これまでの番号・リーチの状況・ビンゴした人のニックネームと順位。終了：最終結果。再読み込みしても状態が戻る |
| F-31 | 抽選の演出・効果音 | MVP | 抽選のたびに番号が決まるまでの演出（アニメーション・効果音）があり、ビンゴが出たときは特別な演出がある。効果音は投影用PCから鳴らす（参加者のスマホからは鳴らさない想定。#6 で決める） |

### やらないこと
| 機能 | 理由 |
|---|---|
| ビンゴ申告と司会の承認 | 自動判定で当選が決まる。申告制にすると、つながっていない人が当選できなくなる |
| ルームのリセット | リハーサル用のルームを別に作ればよい。本番のルームを誤って消す危険を避ける |
| 1つのルームでの2回戦以上 | 1イベント1回の想定。2回戦をする場合は新しいルームを作る |
| 司会の役割ごとの権限分け（MVP） | 同じ司会URLを共有して全員同じ権限で運用する。必要なら次期に検討する |
| 抽選の取り消し | #3 で決定。確認ポップアップと連打防止で誤操作を防ぐ |
| ニックネームの禁止語（MVP） | 社内イベントなので、司会による削除（F-08）で対応する。次期に検討する |
